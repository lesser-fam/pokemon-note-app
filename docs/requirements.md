# 要件定義書

## 1. アプリ概要

Matchup Noteは、ポケモン対戦におけるパーティ構築、選出判断、対戦ログ、振り返りを一元管理する学習支援アプリです。

対戦前に相手パーティを見ながら選出を検討し、対戦後に勝敗・選出・反省点を記録します。記録したログをもとに、現在の構築とパーティ全体の傾向を振り返れるようにすることを目的としています。

## 2. 開発目的

ポケモンのランクマッチで勝ちを重ね、初心者にとって大きな目標となるマスターボール級を目指したい、という自身の課題感から開発しました。

特に初心者のうちは、相手パーティを見たときに「何を選出すればよいか」が分からず、対戦したい気持ちはあっても手が止まりやすくなります。Matchup Noteでは、対戦前の選出判断と対戦後の振り返りを記録しやすくすることで、初心者から中級者手前のユーザーがランクマッチをより楽しみながら上達できることを目的としています。

既存のメモや表計算では、パーティ変更、選出テンプレート、対戦ログが分散しやすいため、対戦前後の判断をひとつの流れで管理できる専用ツールとして開発しました。

## 3. 想定ユーザー

- ポケモン対戦のパーティ構築を記録したいユーザー
- ランクマッチでマスターボール級を目指したい初心者から中級者手前のユーザー
- 対戦ログから自分の選出傾向や敗因を振り返りたいユーザー
- パーティ変更後も過去ログを残しながら改善したいユーザー
- 相手パーティを見て、対戦前に選出を整理したいユーザー

## 4. 利用シーン

- 新しいパーティを作成し、構成・技・持ち物・役割を登録する
- 対戦前に相手6匹を入力し、自分の選出候補を検討する
- 対戦後に勝敗、選出、重かった相手、必要だった味方、反省点を記録する
- パーティ変更時に新バージョンを作成し、変更理由を残す
- 現在の構築とパーティ全体のログ集計を見比べる
- 対戦ログから選出練習を行う

## 6. 非機能要件

| ID | 要件 | 内容 |
| --- | --- | --- |
| NF-01 | 認可 | ユーザーは自分のパーティ・ログのみ操作できる |
| NF-02 | 保守性 | フロントエンドは機能単位のディレクトリで整理する |
| NF-03 | 型安全性 | TypeScriptにより主要データの型を定義する |
| NF-04 | テスト | 認証、認可、パーティ管理、ポケモン登録、バージョン管理、対戦ログ、管理者APIなど重要なAPIにFeature Testを用意する |
| NF-05 | データ保全 | パーティ変更時も過去ログをバージョン単位で保持する |
| NF-06 | 開発容易性 | SQLiteまたはSailを使ってローカル環境を構築できる |
| NF-07 | 初期データ構築 | PokéAPI由来のマスターデータをコマンドで取得・登録できる |

## 7. スコープ外

- 正確なダメージ計算
- オンライン対戦サービスとの自動連携
- ポケモン公式データの定期自動更新
- 複数ユーザー間でのパーティ共有
- 本番運用向けの高度な監視・ログ基盤

## 8. 受け入れ条件

- ユーザー登録後、ログイン状態でパーティを作成できる
- 作成したパーティにポケモンを登録できる
- 対戦ログを作成し、パーティ詳細で集計を確認できる
- 新バージョン作成後も、過去バージョンの対戦ログが総合集計に含まれる
- 他ユーザーのパーティやログを閲覧・編集できない
- 一般ユーザーは管理者向け登録APIを利用できない
